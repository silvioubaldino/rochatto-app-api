# Changelog — <serviço>

All notable changes to this service (specs, implementation, local decisions) are
documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this
project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

**Policy**:
- **Order:** most recent on top; new entries go **above** the previous ones.
- **Unreleased:** unreleased work accrues under `## Unreleased` (always the top block), with
  no date/version. On the releases, `## Unreleased` becomes `## [dd-MM-yyyy - vX.Y.Z]`
  (SemVer) and a new empty `## Unreleased` is opened above it.
- **One line per PR:** each PR adds a **single line** describing summarized what it delivers — general,
  no implementation or docs-framework detail; reference the PR (e.g. `[PR#02](url)`). The
  line **may omit SPEC additions** (tracked by their own files/git): if a PR only adds a
  SPEC, summarize the feature they open.

## Unreleased

- Obligations and movements (SPEC-008, AYD-007): `fornecedores.kind` (STONE default); Obligations (payable/receivable per origin and Payee) kept by triggers from the components, with Installments (plan, covered by the settled amount in due-date order), Settlements and Financial movements; routes `/obligations`, `/settlements`, `/financial-movements`; migration 010 converts Receipts, `purchases.paid_*` and `frete_pago`/`comissao_paga` (self-verifying, best-effort down). **Removed**: `/vendas/{id}/pagamentos` (all), `PATCH /purchases/{id}/payment`, Sale `frete_pago`/`comissao_paga`/`pagamentos`, Purchase `paid_amount`/`paid_at`/`to_pay` (now `paid`/`payable`, derived). `/finance/summary` returns cash, expenses, result and balances; alerts are generated from uncovered installments and account deadlines (`conta_pagar_vencendo`/`conta_pagar_vencida` added, `pagamento_id` replaced by `obligation_id`/`installment_id`). Assistant connector catalog stays `1.0.0` (36 tools): + `list_obligations`, `list_financial_movements`, `settle_obligations`, `record_expense`, `set_installments`; `record_receipt`, `confirm_receipt`, `record_supplier_payment` removed (catalog never released); `kind` on Suppliers.
- Assistant connector write tools (SPEC-007): the 16 write tools (customers, Quotes, Sales, Receipts, Purchases, Supplier payments, Stock adjustments) with risk annotations, 120 s creation deduplication (`allow_duplicate`), `write` scope enforcement and the complete 34-tool catalog `1.0.0`.
- Assistant connector (SPEC-006): OAuth 2.1 server (discovery, DCR, PKCE, rotating refresh tokens with reuse detection, revocation, consent and Connections APIs) and a stateless MCP endpoint `/mcp` with audit, rate limit and the 18 read-only tools; off by default (`MCP_ENABLED`); `GET /dashboard/notificacoes` also returns `pagamento_id` and accepts `only_unread=false`.
- Dashboard (SPEC-005): `GET /dashboard/kpis` (period KPIs with average ticket, Quote → Sale conversion and open balances shared with `/finance/summary`), `quick_sale` flag on Quotes (quick sales excluded from conversion), monthly report with exactly N zero-filled months and `sales_count`, products ranking with `from`/`to` and `unit`; `/dashboard/resumo` deprecated.
- Finance (SPEC-004): payment method on Receipts (required when received) with soft-delete and a lock on canceled Sales, `receivable`/`freight_payable` and new filters (`freight_pending`, `commission_pending`, `from`/`to`) on Sales, `GET /finance/summary` (sales by period, cash movement, open balances) and payment alerts generated by the API (no `pg_cron`, read alerts stay read).
- Sale fulfillment (SPEC-002): item origin (made-to-order / from stock), consolidated Purchases per Supplier with a to-buy queue and one supplier payment, Stock balance with statement and adjustments (replaces `/estoque`), Sale delivery status with cancellation and computed payment status; Sales are only created from Quotes; canceled Sales leave every total.
- Fase 0 — base confiável: corrected Sale summary and dashboard numbers (no more totals multiplied by items × receipts; quantity-weighted average price/cost per Product; monthly Profit with Freight/Commission once per Sale), owner-only access (`ALLOWED_EMAILS`), embedded migrations with `cmd/migrate`, CI, Go 1.26 Docker image, ops/backup notes.
- Commercial registries (SPEC-003): `/partners` with type replaces `/vendedores-externos`; Customer lead source (+ referring Partner); Product categories (`/product-categories`) and `category_id` on Products.
- Quote → Sale hardening: quote without supplier, quick sale, Sale exposes its origin Quote, safer delete/convert, PATCH allowed by CORS, business-timezone dates, integration tests.
- Implement SPEC-001: Quote entity (CRUD + items), status transitions (OPEN/WON/LOST) and transactional `POST /quotes/{id}/convert` into Sale; wire `cmd/server/main.go` bootstrap.
